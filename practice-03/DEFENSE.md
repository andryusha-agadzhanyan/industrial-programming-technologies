# Как понять и защитить практическую №3

## 1. Что получилось

Это браузерный список задач. Можно посмотреть все задачи, только невыполненные или только выполненные; изменить статус и удалить задачу. Сводка показывает весь список, а «Показано» — только число карточек выбранного фильтра. После перезагрузки восстанавливаются исходные данные: сохранение относится к следующей работе.

Работа продолжает ПР2. Функции создания, поиска, изменения, удаления и статистики уже были написаны там. В ПР3 к ним добавлены карточки и кнопки в браузере. Используются обычные JavaScript, HTML и CSS, без установленных зависимостей приложения.

## 2. Что открыть на защите

В Terminal перейти в папку `practice-03` и выполнить:

```bash
npm run check:service
npm start
```

Открыть `http://127.0.0.1:5503/`. Затем показать ссылку «Свой вариант» и страницу «Проверки». Терминал с сервером должен оставаться открытым. Для остановки нажать Ctrl+C. `npm install` не нужен.

Нельзя запускать интерфейс как `node src/main.js`: объект `document` предоставляет браузер. Открывать `index.html` двойным щелчком тоже не следует: импорты модулей должны загружаться через локальный HTTP-сервер.

## 4. Как хранятся данные

Одна задача — объект `{ id, title, completed, priority }`. `id` — постоянный номер задачи, а не индекс массива. Например, задача с id=4 стоит на второй позиции общего массива. `completed` — логическое значение true/false, а приоритет — строка low/medium/high.

В `main.js` есть две переменные:

```js
let currentTasks = initialTasks.map((task) => ({ ...task }));
let currentFilter = "all";
```

`currentTasks` хранит **полный** актуальный список. Создаётся копия массива и каждого объекта, чтобы не менять экспортированные исходные данные. `currentFilter` хранит выбранное условие показа. Результат фильтрации в `currentTasks` не записывается, иначе скрытые задачи потерялись бы.

## 5. Фильтр — самая короткая функция

`getVisibleTasks` использует `filter` для pending/completed и `[...tasks]` для all. Во всех случаях возвращается новый массив, порядок сохраняется. Объекты не меняются.

Если исходные id `[1,4,7,10]`, выполнены 1 и 10, то pending вернёт `[4,7]`, completed — `[1,10]`. После возврата на all снова видны все четыре.

## 6. Как создаётся карточка

`document.createElement("li")` создаёт отдельный объект элемента, но ещё не вставляет его на страницу. Для карточки назначаются класс `task-card` и `data-task-id`. Класс `is-completed` добавляется только выполненной задаче.

Затем создаются заголовок, статус, приоритет и две кнопки. Внутри каждой кнопки есть `span.action-label`: по нему тоже можно нажать. `textContent` задаёт текст; название `<strong>Проверка</strong>` появится как строка со скобками, не превратится в HTML.

В конце `card.append(...)` собирает содержимое. Метод возвращает карточку, а `renderTaskList` создаёт карточки всех видимых задач и вызывает `listElement.replaceChildren(...cards)`. Старые дочерние элементы заменяются, поэтому при повторной отрисовке список не удваивается. Сам `ul` сохраняется вместе с его обработчиком.

## 7. Одно нажатие от начала до конца

Пример: пользователь нажимает подпись «Выполнена» у id=4.

1. Исходная цель `event.target` — вложенный `span`.
2. Событие всплывает до `ul#task-list`, на котором зарегистрирован обработчик. В нём `event.currentTarget` — этот `ul`.
3. `closest("button[data-action]")` находит кнопку, `button.dataset.action` даёт строку `toggle`.
4. Ближайшая карточка содержит `dataset.taskId`, то есть строку `"4"`.
5. `Number` превращает её в число 4. `Number.isSafeInteger` и `id > 0` проверяют допустимость.
6. `findTaskById(currentTasks, id)` находит задачу, из её данных берётся текущий `completed`.
7. `setTaskCompleted(currentTasks, id, !task.completed)` возвращает результат. Для false выражение `!false` даёт true.
8. При `result.ok` новый массив сохраняется в `currentTasks`; сообщение об ошибке очищается.
9. `renderApp()` заново обновляет карточки, счётчики, пустое состояние и фильтры.
10. `restoreTaskFocus` возвращает клавиатурный фокус на действие этой задачи или на активный фильтр, если карточка исчезла.

Для удаления путь такой же, только вызывается `removeTask`. Простое удаление HTML-элемента не решает задачу: при следующем рендере запись вернулась бы из массива.

## 8. Почему обработчиков всего два

Один обработчик находится на списке задач, второй — на панели фильтров. Это **делегирование событий**: контейнер принимает всплывающие события дочерних элементов. Подписки выполняются один раз, в конце `main.js`, а не внутри `renderApp`.

Если назначать новые обработчики контейнеру после каждого рендера, один клик может вызвать несколько операций. `closest` нужен потому, что клик бывает по span внутри кнопки. `contains` проверяет, что найденный элемент относится к нужному контейнеру. Неизвестные действия и фильтры игнорируются.

## 9. Откуда берутся счётчики

`renderSummary` вызывает готовый `getTaskStats(currentTasks)`. Он считает весь список, даже если часть карточек скрыта. Процент форматируется как `stats.progress.toFixed(1) + "%"`. Число видимых берётся из `visibleTasks.length`.

Например, в начале 4 задачи, 2 выполнены, прогресс 50.0%. Выбор «В работе» оставляет две карточки, но общая сводка остаётся 4/2/2/50.0%. Меняется только «Показано»: 2.

## 10. Два разных пустых состояния

Если весь список пуст, сообщение: «Список задач пуст.». Если задачи есть, но фильтр никого не выбрал: «Нет задач по выбранному фильтру.». Когда карточки есть, текст очищается и `hidden=true`. В пустой сводке прогресс 0.0%: деления на ноль нет, это обрабатывает сервис ПР2.

## 11. Ошибки и защита идентификатора

`dataset` всегда отдаёт строку. `Number("4abc")` даёт NaN, а `parseInt("4abc")` мог бы ошибочно дать 4. Поэтому используется полное преобразование через Number. Число 777 допустимо по формату, но такой задачи нет: сервис сообщает об отказе. При отказе не присваивается `result.tasks`, потому что такого поля нет в объекте `{ ok:false, error:... }`.

После корректного выбора фильтра карточки восстанавливаются из реального массива и сообщение очищается. Статус задачи берётся из данных, а не из цвета, CSS-класса или текста кнопки.

## 12. Индивидуальный вариант №3

Тема — создание сайта-портфолио. Перенесены те же шесть задач из ПР2: `[11,23,37,41,58,64]`. Первые две выполнены.

- Начало: всего 6, выполнено 2, осталось 4, прогресс 33.3%.
- Переключили id=23: она стала невыполненной; 6/1/5/16.7%.
- Удалили невыполненную id=37: 5/1/4/20.0%.
- Итоговые id: `[11,23,41,58,64]`; в работе `[23,41,58,64]`, выполнена `[11]`.

Специального расчёта «если вариант 3, вывести 20» нет. Результат получается из общих функций и конкретных данных.

## 13. Пять экспериментов

1. `querySelector` при отсутствии совпадения возвращает null. `querySelectorAll` возвращает пустую коллекцию длиной 0.
2. `dataset.taskId` имеет тип string; после `Number` тип number.
3. Сохранённый NodeList от `querySelectorAll` — снимок. После двух добавлений его длина остаётся 1, новый запрос видит 3.
4. `textContent` выводит строку с `<strong>` буквально, дочерний HTML-элемент не создаётся.
5. При клике по span внутри кнопки: захват на контейнере (фаза 1), обработчик кнопки при всплытии (фаза 3), всплытие на контейнере (фаза 3). Цель — span; currentTarget меняется для каждого обработчика.

## 14. Что показать преподавателю за три минуты

Открой общий набор, выбери «В работе», выполни id=4: карточка исчезнет, общий прогресс станет 75.0%. Верни «Все», удали id=7: останутся три выполненные задачи. Выбери «В работе» и объясни сообщение об отсутствии совпадений. Затем покажи вариант №3 и его итог 20.0%. Открой проверки и назови реальный результат из отчёта.

В коде открой `main.js` и проведи преподавателя по одному событию из раздела 7. Потом покажи `task-view.js`: почему используется textContent и почему replaceChildren не заменяет сам ul.

## 15. Возможные небольшие изменения на защите

Чтобы изменить подпись приоритета, достаточно поменять словарь `priorityNames` в `createTaskElement`. Чтобы показать другой набор, меняются данные, а алгоритм остаётся общим. Чтобы изменить точность процента, меняется аргумент `toFixed` в `renderSummary`, но в сдаваемой версии нужен один знак по условию. Добавление формы или сохранения потребует следующего этапа работы.

Короткая формулировка: «Я подключил браузерное представление к функциям ПР2. Полный массив хранится отдельно от фильтра. События делегируются контейнерам; после успешной операции сервис возвращает новый массив, а интерфейс полностью обновляется. Исходные наборы сохраняются, сообщения об ошибке не повреждают данные».
