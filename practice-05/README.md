## 2. Запуск

Из папки `practice-05` в первом терминале:

```bash
npm start
```

Во втором терминале из той же папки:

```bash
npm run example:order
npm run example:fetch
npm run client -- --demo
npm run client
npm test
npm run check:own
```

Учебный сервер доступен по `http://127.0.0.1:5505/api`. Параметр `--demo` запускает общий контрольный сценарий, запуск без параметра использует вариант 3. Для тестов отдельный сервер не нужен.

## 3. Очереди выполнения

| Запуск | Прогноз | Фактический порядок |
|---|---|---|
| Исходный пример | A → B → C → D → E → F | A → B → C → D → E → F |
| После добавления обработчика G | A → B → C → D → E → G → F | A → B → C → D → E → G → F |

A, B и C выполняются сразу, включая начало `async`-функции до `await`. Обработчик Promise ставится в очередь перед продолжением после `await`, дополнительный обработчик G ставится после них. Таймер F выполняется после микрозадач.

## 5. Реализация клиента

`api-client.js` формирует адрес через `URL` и `URLSearchParams`. Пустая строка, `null` и `undefined` пропускаются, а `false` и `0` сохраняются. Например, строка `API & ошибки` после разбора параметров возвращается целиком. Исходный объект параметров не меняется.

`requestJson` отправляет GET с `Accept: application/json`, проверяет HTTP-статус и заголовок ответа, затем разбирает тело. Для 204 возвращается `null`. Внешний сигнал и тайм-аут объединяются через `AbortSignal.any`. `task-api.js` проверяет допустимые фильтры до запроса, а после него сверяет поля записей, уникальность id и `meta.total`.

| Сценарий | Ожидаемый тип ошибки | Фактический результат |
|---|---|---|
| Сервер вернул 404 или 503 | `http` | 404 `TASK_NOT_FOUND` и 503 `SERVICE_UNAVAILABLE`. |
| Сервер остановлен | `network` | Консоль показала «Не удалось связаться с сервером», запуск завершился с кодом 1. |
| Статус 200 с текстом или повреждённым JSON | `invalid-response` | Оба ответа отклонены как `invalid-response`. |
| Задержка 150 мс при лимите 20 мс | `timeout` | `kind = timeout`. |
| Вызов `abort()` при лимите 1000 мс | `aborted` | `kind = aborted`. |

## 9. Отладка и вывод

Для запроса задачи 999 учебный сервер вернул полноценный объект `Response` со статусом 404. Отдельная ветка `response.ok` сохранила статус и код. После остановки сервера отказ произошёл раньше, во время самого `fetch`, и был классифицирован как `network`. Это позволяет вывести причину ошибки в консоль и понять, что проверять.
